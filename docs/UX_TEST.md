# 第 0 周 Spike · 交互原型 UX 测试脚本

> 目标：验证「提议-采纳-回滚」协作交互能否被**非技术用户**在 30 秒内理解并认可价值。
> 原型位置：`frontend/prototype/index.html`（纯静态，双击即可在手机/电脑浏览器打开，无需服务器）
> 前置：事件溯源引擎原型已通过 22 个单测（`python -m pytest`），交互原型已通过 8 项自动化交互断言。

## 一、通过 / 不通过判据（先行约定，测试中不修改）

| 判据 | 通过标准 |
|---|---|
| **理解速度** | ≥3/5 名用户在 30 秒内能说出「提议 ≠ 直接改定稿」 |
| **价值认可** | ≥4/5 名用户回答「比微信群好在哪里」时提到：定稿不乱、能对比、能反悔（任意一条） |
| **二次使用** | 测试过程中 ≥3/5 名用户**主动**发起第二次提议（不是主持人引导的） |
| **自然回滚** | 场景 D 中 ≥3/5 名用户不需要提示就找到并完成回滚 |
| **致命反馈** | 无人说出「不如直接在群里说」（若 ≥2 人说，判不通过） |

不通过 → 回到设计：简化交互模型（如去掉「待审核」态、采纳按钮直接化），重测。

## 二、测试准备

- **招募**：3~5 名**真实即将出行**的朋友/家人（正在规划一场旅行的小队最优）。至少 1 名非技术背景，至少 1 名平时爱抬杠/提反对意见的（避免全是附和者）。
- **设备**：每人一部手机（原型移动端优先）；主持人另备一台可分享屏幕的设备。
- **环境**：打开 `frontend/prototype/index.html`，首页即西安 3 日游演示数据。
- **告知（必须说）**：「这是一个旅行协作工具的原型，里面是假数据。请把阿杰当成你，你是创建者。像平时聊天一样操作，卡住就直接说。」

## 三、场景脚本

### 场景 A：规划期 · 有人提议换酒店（验证「提议≠直接改」）
1. 引导：「小雨提议 D1 晚餐改吃泡馍，已经生效了，你看到定稿里变了吗？」（定位已采纳卡片）
2. 请用户**自己找到**提议中心，找到老王「D2 上午华清宫下午兵马俑」这条待审核提议。
3. 追问：「这条还没生效，你觉得它现在会不会影响大家看到的行程？」→ 观察是否理解「待审核」。
4. 让用户执行采纳（预期出现确认弹窗）。追问：「刚才为什么要你再确认一次？」
5. 回到定稿行程，确认变更已合并。

### 场景 B：规划期 · 依赖告警（验证冲突提示可理解）
1. 让用户打开阿杰的「D1 改乘中午的高铁」提议，**不点开讨论**先看卡片上的提示。
2. 追问：「卡片上那个黄字提示在说什么？」（预期：改高铁会连累兵马俑）
3. 让用户采纳 → 观察确认弹窗里是否读懂了「兵马俑」被引用。
4. 追问：「如果两条提议都改同一个安排，系统该听谁的？」（观察是否自然说出「要人决定」）

### 场景 C：旅途中 · 景区临时闭园（验证应急路径）
1. 口头情境：「到兵马俑发现临时闭园，现在你人在现场，怎么办？」
2. 看用户是否**自己找到**「旅途应急」按钮（不给提示，找 30 秒找不到再指）。
3. 让用户完成「出问题了 → 立即生效」。追问：「现在大家手机上能看到吗？原来的安排还在吗？」
4. 让用户尝试「撤销」，追问撤销后发生了什么。
5. 关键观察：**用户是否理解「临时备选 ≠ 正式定稿」**（若混淆，记严重问题）。

### 场景 D：反悔（验证回滚）
1. 引导：「觉得刚才合并错了，想回到最早那版」，不给提示，看用户能否在「版本」页找到回滚。
2. 追问：「回滚之后，以前被采纳的提议记录还在不在？」

## 四、主持人观察清单（每用户一张，打勾）

- [ ] 30 秒内理解「提议是提议、定稿是定稿」
- [ ] 主动发起第二次提议（非引导）
- [ ] 卡顿点在哪一步（记下来，供改交互）
- [ ] 提到/误用任何术语：「分支」「PR」「提交」「合并申请」（出现 = 记录是界面哪处诱导的）
- [ ] 旅途应急是否自然找到（<30 秒为合格）
- [ ] 撤销/回滚是否无需提示完成
- [ ] 「不如微信群」类抱怨（出现次数）
- [ ] 全程耗时 vs 对照组（同场景用微信群/文档规划的耗时，粗估即可）

## 六、防假阳性提醒

1. **行为优先于表态**：「挺有用的」不算数；「主动再提一条提议」才算数。
2. **招募真实出行群体**，不要找全技术人员；用真实任务而非「模拟一下」。
3. 主持人只引导、不解释产品逻辑；解释过一次的动作，第二次再出现就不算用户独立完成。
4. 测试完 24 小时后回访一次：「你还会再用它吗」——留存意愿比当场满意度更真实。

## 七、原型能力速查（主持人背熟）

- 视图：底部导航 行程/提议/＋(新建)/版本/通知；行程页右下角「⚡旅途应急」。
- 提议卡片：理由、变更明细、黄色依赖告警、讨论区、采纳/拒绝。
- 采纳弹窗：多改动或依赖告警时会要求确认；硬冲突（另一条提议改同一条目）会提示人工判断。
- 临时备选：提交即生效、全员可见，卡片上可「正式化」或「撤销」。
- 版本页：每次采纳/回滚生成一个版本，任意旧版本可一键回滚（历史保留）。
