# 需求规格说明（V1.3 修订版要点）

> 版本：V1.3（合并所有讨论：版本协作、途中临时变更场景、预算模块、数据源插件降级策略、UX 约束、分阶段开发计划、开源复用策略）

## 核心前提

- 底层采用**事件溯源模型**；上层产品界面完全隐藏分支/PR/Git 术语，用户仅感知【定稿行程、提议、采纳、拒绝、回滚】。
- 所有外部数据源、AI、攻略能力均为**可降级插件**，核心协作模块不依赖任何第三方接口。
- 定位：多人长途结伴旅行的行程方案协作工具，仅做信息查询展示，预订跳转官方平台，不实现购票、支付。

## 一、核心设计原则（架构规范）

1. **核心优先**：提议协作、版本快照、通知系统是核心；AI、爬虫、OTA 查询全部为可选插件。插件失效，主协作系统依旧完整可用。
2. **事件溯源**：定稿行程 = 所有已采纳提议的事件顺序回放结果；不直接覆盖原始行程数据，天然支持回滚。
3. **AI 隔离**：AI 生成内容仅作为提议草稿，AI 不能直接写入定稿行程，必须人工审核。
4. **用户体验优先**：底层逻辑可复杂，前端交互极简，禁止向普通用户暴露任何技术术语。
5. **功能分层**：MVP 只验证核心协作闭环；增值能力全部后置迭代。

## 二、核心模块：提议式版本协作

### 底层数据模型：事件溯源

- 每一次修改拆分为不可变操作事件：新增条目 / 修改条目 / 删除条目。
- 一份提议 = 一组批量操作事件。未采纳前，仅存在于提议草稿，不污染定稿行程。
- 定稿行程 = 所有**已采纳提议**按时间顺序回放生成。

### 用户可见交互（无分支/PR 术语）

1. 新建旅行项目，创建空白定稿行程，邀请团队成员，分配角色：创建者、管理员、普通成员、只读成员。
2. 成员可创建**提议**：修改内容 + 理由，可附加链接、图片、AI 生成内容、攻略摘要。
3. 状态流转：草稿 → 待审核 → 已采纳 / 已拒绝。
4. 待审核阶段可评论讨论。
5. 采纳 = 合并进定稿；拒绝 = 丢弃变更但保留完整记录。
6. 历史快照与回滚：查看全部历史定稿版本，一键回滚至任意快照，原始计划永久保存。

### 冲突判定规则

- **软冲突**：修改不同条目，允许自动合并，人工复核确认。
- **硬冲突**：多个提议同时修改**同一条目**，禁止自动合并，强制人工判定。
- **隐性依赖冲突**（如 D2 酒店依赖 D1 抵达车次）：系统仅标记告警，交人工判断。
- **（补充约定）** 冲突检测发生在**采纳动作执行时**，基于当前已回放的定稿状态，而非提交时快照。

### 审核瓶颈解决方案

- 默认模式：管理员审核。
- 可选投票模式：达到预设票数阈值自动采纳。
- 超时机制：超 N 天未处理自动标记超时提醒，可配置自动归档。

### 通知系统

- MVP：应用内通知（新提议、被采纳/拒绝、新评论、超时提醒）。
- 二期：PWA 浏览器推送；建议 MVP 补一条廉价推送通道（Server酱/钉钉/邮件 webhook）保障审核闭环。

### 离线策略

- MVP：仅离线**只读**（可查看定稿，不可新建/提交提议）。
- 二期：支持离线保存提议草稿，联网后提交。

### 旅途临时变更能力（应对景区闭园、超时、换路线）

1. **快速提议入口**：应急场景专用快捷按钮，一键新建简化版提议，降低手机输入成本。
2. **临时备选方案**：紧急情况下可标记「临时备选」；**建模为"提交即采纳的紧急提议"**（事件溯源保持单一真相，可回滚、可事后正式化/撤销）。
3. **AI 时间线连锁推演**：改一条时间后向后推演整条时间线，识别冲突并给出多套调整方案，可一键填充进提议草稿（硬约束传播用规则引擎，LLM 只负责生成方案文案）。
4. **短途交通插件**：点位间查询打车/公交/骑行，预估耗时费用，可一键新增为行程条目；失效时可手动录入。
5. 景区公告预警插件（三期）：拉取官方公告，预警闭园/限流/临时活动；增强能力，失效不影响手动提交。

## 三、预算模块（二期；MVP 仅预留金额字段）

- MVP：行程条目预留金额字段，手动录入预估/实际金额，不做自动汇总。
- 二期：条目绑定费用（预估/实际、付款人、分摊成员、备注）；提议预算变动预览；分类统计报表；总预估/实际对比；AA 分摊；预算超支告警。
- **（补充约定）** AA 分摊为独立小引擎，与"预算记录"拆分排期。

## 四、国内数据源插件（全部可降级）

- 12306 插件：车次、时刻表、换乘方案、余票参考；仅展示，跳转官方渠道购票。
- OTA 酒店插件：酒店/民宿查询、房型、价格、评分、评价参考；跳转官方预订页。
- 攻略插件：小红书、马蜂窝游记抓取 + AI 摘要，过滤软文，提取避坑/游玩建议，可关联行程景点。
- 风险备注：逆向接口/爬虫维护成本高，平台风控升级会造成失效；系统内置开关可一键禁用。参考 Voyago 的 12306 skill 实现思路自研封装，增加异常捕获与降级。

## 五、AI 能力模块

1. AI 行程生成：输入出行参数生成结构化行程，**输出为提议草稿**。
2. AI 行程校验：检测时间冲突、距离不合理、开放时间异常，给出风险提示。
3. AI 对话助手：项目内问答，可读取当前定稿与攻略知识库。
4. RAG 攻略知识库（三期）：游记向量化入库，基于真实游记做问答与推荐。

## 六、风险清单

1. **用户心智风险（最高）**：提议审核机制带来摩擦，仅适合多人长途多方案讨论场景。第 0 周 UX 测试验证。
2. **数据源长期维护成本高**：12306 逆向、小红书爬虫易失效；产品卖点不绑定爬虫，数据源仅为增强插件。
3. **隐性冲突判定复杂**：跨条目依赖需人工兜底；建议以"条目引用"显式建模依赖（D2 酒店引用 D1 车次），有引用图则可自动检测，未建模的依赖只做粗粒度告警。
4. **AI 幻觉风险**：AI 输出强制仅为提议草稿，人工审核后并入定稿。

## 七、分阶段开发计划

### 第 0 周：Spike 原型验证（最高优先级，不写正式业务代码）

1. 极简事件溯源原型：提议、合并、回滚、冲突判定纯后端逻辑 + 单元测试。
2. 简易交互原型 + 3~5 名真实即将出行群体 UX 测试（更换酒店、景区闭园快速提议场景），用行为指标（是否主动二次使用、是否自然用回滚）而非满意度判断。
- ✅ 通过 → 进入 MVP；❌ 不通过 → 调整交互模型或终止。

### 阶段 1：MVP（核心协作闭环）

- 创建项目、邀请成员、基础角色权限
- 定稿行程时间线展示
- 提议全流程：草稿 → 提交 → 采纳/拒绝（支持逐条部分采纳）
- 历史快照、版本回滚
- 应用内通知
- 快速提议入口（旅途应急）
- 最简 AI 生成（输出到提议草稿）
- 离线只读
- 预算金额字段（仅录入）
- 数据源插件预留接口（Mock 数据）

### 阶段 2：数据源插件 + 预算模块

- 12306 / 酒店查询插件 + 降级开关
- 短途交通查询插件
- 完整预算：自动汇总、分类统计、AA 分摊、提议预算变动预览、预算告警

### 阶段 3：AI 与攻略增强

- 小红书攻略抓取 + AI 摘要
- RAG 知识库、基于游记问答
- AI 时间线连锁推演、行程冲突检测
- 景区公告预警插件

### 阶段 4：体验完善（二期增值）

- 行李清单、天气联动、PWA 推送、离线草稿、评论投票、图片附件管理

## 八、开源复用策略（修正版）

1. **TripStar**（GPL-2.0）：核心代码基座？——否。**仅模块级移植** AI 生成（多智能体编排、prompt 工程、xhs 解析）。移植即触发 GPL-2.0，接受或重写二选一。
2. **Voyago**（MIT）：参考/移植 12306、高德、酒店数据封装逻辑，自研封装 + 异常捕获 + 降级开关，独立插件化。
3. **TREK**（AGPL-3.0）：产品/UI 思想参考，不移植代码（React 栈 + AGPL 传染）。

## 九、架构核心开发规范

1. 核心优先原则：提议、版本、通知是核心；AI、爬虫、OTA 全为可选插件。
2. 事件溯源模型：定稿 = 已采纳事件回放结果，不直接修改原始数据。
3. AI 不可直接写定稿：只能生成提议草稿，人工审核后合并。
4. 用户体验优先：底层可复杂，前端极简，杜绝术语暴露。
5. 插件降级原则：所有外部 API 调用必须有异常捕获、开关控制，异常时优雅降级，不阻塞主流程。
